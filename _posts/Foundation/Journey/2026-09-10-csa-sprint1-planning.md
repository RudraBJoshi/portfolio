# CSA Sprint 1 — Ground 0 Onboarding Plan

Sprint 1 for AP CSA is "Ground 0": prove I can operate my dev environment, my GitHub workflow, and my team without waiting on anyone else — then get a team and a project direction off the ground. Of the five Onboarding Objectives, **planning is what I'm weighting heaviest** this sprint: objectives 4 and 5 (forming the team, beginning the project) are where a real plan turns into evidence instead of a last-minute scramble before the checkpoint.

This plan is a living document — I'll check items off and add evidence links as the sprint actually happens, not backfill it at the end.

## 1. Understand the Challenge
- [ ] Write, in my own words, why Ground 0 is about *working through* an unfamiliar environment, not just installing tools
- [ ] Identify one problem I hit and document how I solved or investigated it
- [ ] Document something from my setup that could help another student
- [ ] Capture my team-formation story (positives + challenges) as I go
- [ ] Capture my project-start story (positives + challenges) as I go

## 2. My Development Environment
- [ ] Confirm I can open my dev environment and start working independently
- [ ] Confirm I can edit and preview course files
- [ ] Confirm Git/GitHub commit + push works end-to-end
- [ ] Bookmark the tool setup / troubleshooting guides I actually needed
- [ ] Know my go-to path for asking for help when stuck
- [ ] Write my working strategy for my personal computer / dev environment

## 3. My GitHub Workflow
- [ ] Locate my GitHub repository
- [ ] Create an issue in my repository
- [ ] Commit a change via GitHub directly
- [ ] Create/edit a file in VSCode
- [ ] Commit and sync a change from VSCode to GitHub
- [ ] Check GitHub Actions and confirm my site build status
- [ ] Load my GitHub Pages portfolio site in the browser

## 4. Forming the Team — this is the core planning work

**Before Forming the Team**
- [ ] Review the team formation process
- [ ] Read the article on selecting effective development teams
- [ ] Write out my persona: skills, interests, strengths in OCS
- [ ] Note the expectation for diversity of skills/interests/perspectives
- [ ] Shortlist teammates I'd likely work well with, based on skills not just friendship

**Establishing the Team**
- [ ] Learn my team members' names
- [ ] Hold a discussion on our skills, interests, perspectives
- [ ] Set up our team communication channel
- [ ] Share my preferred contact method with teammates
- [ ] Draft our team Agile manifesto + communication protocols

**Beginning to Operate as a Team**
- [ ] Identify the coding challenges required for the course
- [ ] Create team and individual GitHub repositories
- [ ] Create team and individual GitHub issues, kanban board, milestones
- [ ] Start team decision-making rhythms: stand-ups, pin-ups, burndowns
- [ ] Practice Live Share / debugging / pair programming once
- [ ] Agree on how we discuss problems and resolve issues
- [ ] Agree on contribution workflow: fork / branch / PR / direct collab
- [ ] Agree on how we take and act on feedback between checkpoints

## 5. Beginning the Project
- [ ] Participate in project ideation
- [ ] Write one sentence describing a project idea the team is considering
- [ ] Contribute an idea, question, research finding, or technical point
- [ ] Open a GitHub issue tied to the work
- [ ] Land on our first project direction as a team
- [ ] Write down what I personally owe before the next checkpoint
- [ ] Write down what the team owes before the next checkpoint
- [ ] Remember: presenting evidence is part of the work, not an afterthought

## Team Activities Map

| Phase | Cycle | Focus |
|---|---|---|
| Team Formation | Understand → Introduce → Explore → Form | Group by skills/interests/perspectives/project needs, not just friendship |
| Team Initialization | Organize → Connect → Decide → Build | Comms, GitHub workflow, coding practices, decision process, first direction |
| Team Practice | Communicate → Collaborate → Solve → Document | Daily checkpoints, issue tracking, pair programming, evidence collection |

## End-of-Sprint Target

Following the Sprint Review Cycle: Team Capability Review → Peer-to-Peer Presentation → Feedback → Refinement & Iteration → Teacher Close-Out → Individual Mastery Review → Goals for Sprint 2.

Before that review, I want:
- Every checkbox above either checked with evidence linked, or explicitly carried into "what I still owe"
- A short reflection ready comparing my team-formation and project-start stories to what I planned here
