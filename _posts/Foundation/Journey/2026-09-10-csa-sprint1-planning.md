# CSA Sprint 1 — Onboarding Challenge Plan

Sprint 1 for AP CSA is the Onboarding Challenge: get my tools set up, get my team and personal repos running, and be able to explain the SDLC in my own words. Of everything in the rubric, **planning** carries the most weight for me this sprint — a good plan is what turns the checklist into finished, provable work instead of a scramble in week 4.

## Mission, in my own words

I'm relearning the same setup/collaboration muscle I built last year in CSP, but this time as the more experienced student on my team: get VSCode, Git, and GitHub Pages working, document the setup as I go (so my notes double as help for teammates), and end the sprint with my own individual site live and my team's repo functioning.

## Sprint Plan (Agile Setup)

Working backwards from the Sprint 1 Assessment Matrix (Problem statement / setup 25%, quantified specs 25%, research depth 25%, agile sprint setup 25%), I'm breaking the 4 weeks into a small kanban:

### Week 1 — Tools & Team Foundation
- [ ] Verify laptop / cloud workspace meets requirements
- [ ] Install and configure VSCode + Marketplace extensions (LiveShare, GitLens)
- [ ] Fork the OCS student repo; confirm GitHub Actions builds and publishes
- [ ] Join team Slack channel/DM; share contact info with teammates
- [ ] Draft team norms: coding standards, communication protocol, standup cadence

### Week 2 — Workflow & Collaboration
- [ ] Run through the full SDLC loop once: edit → `make` → commit → push → Action deploy
- [ ] Practice a pair-programming / LiveShare session with a teammate
- [ ] Open GitHub issues for each outstanding onboarding task (personal + team)
- [ ] Log first troubleshooting notes (whatever actually breaks, with the fix)

### Week 3 — Portfolio Prep
- [ ] Identify my signature contribution(s) to the team repo so far
- [ ] Write a reflection for each one (what I built, what I'd do differently)
- [ ] Sketch my personal portfolio theme/branding direction
- [ ] Keep a running list of mistakes + lessons to fold into the retrospective

### Week 4 — Personal Launch
- [ ] Fork team repo into my personal repo (this repo)
- [ ] Customize site (theme, about page) with my own design choices
- [ ] Publish a "From Team to Individual" reflection post
- [ ] Set my personal blogging cadence for the rest of the sprints

## Team Norms (draft)

- **Communication:** Slack for day-to-day, sync in class for anything blocking.
- **Commits:** small, descriptive, one topic per commit — easier for teammates to review.
- **Standups:** quick async check-in at the start of class — what I did, what's next, what's blocking me.
- **Code review:** PRs into the team repo get at least one teammate read before merge.
